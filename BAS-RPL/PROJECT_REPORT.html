Abstract

In Internet of Things (IoT) and Wireless Sensor Networks (WSNs), resource-constrained nodes operate under strict bandwidth, buffer, and battery constraints. The standardized Routing Protocol for Low-Power and Lossy Networks (RPL, RFC 6550) establishes a Destination-Oriented Directed Acyclic Graph (DODAG) using Objective Functions like MRHOF (RFC 6719) with Expected Transmission Count (ETX) as the path metric. While ETX delivers reliable forwarding in static scenarios, it is completely blind to buffer queues. During sudden event-driven traffic bursts, packets converge on common bottleneck relays, leading to buffer overflow and heavy drop-tail packet loss.

This project designs and implements BAS-RPL (Burst-Aware Stability-Constrained Routing Protocol). BAS-RPL incorporates proactive queue growth prediction via Exponential Moving Average (EMA) smoothing, an adaptive multi-metric routing cost function, and route stability barriers (cooldown and hysteresis) to eliminate route oscillation. Simulated on a 30-node wireless sensor mesh under identical traffic arrivals, BAS-RPL reduced buffer overflow packet drops by 87% (from 128 drops down to 17 drops), delivering +5.7% higher Packet Delivery Ratio (PDR) and reducing routing control overhead.

1. Introduction & Background

Low-Power and Lossy Networks (LLNs) connect embedded IoT devices across smart agriculture, healthcare telemetry, and industrial monitoring. These devices operate on IEEE 802.15.4 wireless radios, featuring maximum frame sizes of 127 bytes, transmission speeds of 250 kbps, and finite microcontroller RAM buffers capable of queuing only 15 to 30 packets.

RPL (RFC 6550) is the de-facto standard routing protocol for LLNs. It constructs a loop-free Destination-Oriented Directed Acyclic Graph (DODAG) rooted at a central Gateway (Sink). Nodes exchange DODAG Information Objects (DIO) and Destination Advertisement Objects (DAO) to compute scalar Ranks and select preferred parents toward the sink.

2. Problem Statement: The Bottleneck Relay Breakdown

Standard RPL relies on MRHOF (RFC 6719) using Expected Transmission Count (ETX):

PathETX(u) = PathETX(p) + LinkETX(u, p)

Because link ETX only monitors wireless channel retransmissions, it does not reflect buffer occupancy. When an environmental event triggers a burst of packets across a sensor cluster, all nodes select the single relay offering the lowest ETX.

The Failure Mechanism: The bottleneck relay receives packets faster than its service rate. Its 20-packet queue saturates to 100%, triggering massive drop-tail packet loss. Meanwhile, neighboring relays sit completely idle with 0% queue occupancy because their ETX is fractionally higher. Standard RPL cannot bypass the congested relay because the physical radio link remains functional.

3. The Proposed BAS-RPL Protocol

BAS-RPL addresses this limitation through four coordinated innovations:

3.1 Proactive Queue Growth Prediction

BAS-RPL tracks buffer velocity ΔQ = Q(t) − Q(t−1)Δt and applies Exponential Moving Average (EMA) smoothing (α = 0.40) to prevent false alarms:

EMA(t) = α · ΔQ(t) + (1 − α) · EMA(t − 1)

The queue length is projected H = 2 steps into the future:

Qpred(t) = max(0, Q(t) + H · EMA(t))

Yielding a normalized Congestion Index:

C(t) = min(1.0, Qpred(t)Qmax)

3.2 Multi-Objective Adaptive Cost Function

Candidate parent j is evaluated by node i using a normalized cost function:

Cost(i, j) = w1 · ETX(i, j) + w2 · Delay(j) + w3 · Cj(t) + w4 · Penaltyenergy(j)

Configured with weights: w1 = 0.35 (ETX), w2 = 0.15 (Delay), w3 = 0.35 (Congestion), and w4 = 0.15 (Energy).

3.3 Route Stability & Anti-Flapping Constraints

To prevent nodes from oscillating between two relays as their queues fluctuate, BAS-RPL enforces:

  • Cooldown Period (Tcooldown = 4 steps): Enforces a minimum hold time on newly selected parents to prevent rapid route toggling.
  • Switching Hysteresis Barrier (δ = 18%): A new parent candidate must offer at least an 18% cost improvement over the currently selected parent.

3.4 Loop-Freedom Guarantee

Candidates must strictly satisfy monotonic rank and depth constraints:

HopDepth(p) < HopDepth(i)  ∨  (HopDepth(p) == HopDepth(i)  ∧  Rank(p) < Rank(i))

Additionally, an upstream cycle-checking function verifies that the node itself does not appear in the candidate's path to Gateway 0.

4. Simulation Setup & Benchmark Results

A discrete-time simulation of 30 wireless sensor nodes was executed over 50 steps using identical packet arrival seeds (Seed 42). A concentrated traffic burst was injected at steps 15–24 on a sensor cluster.

6. Conclusion

The BAS-RPL protocol successfully addresses the congestion-blindness of standard RPL (MRHOF). By proactively predicting queue growth and enforcing route stability barriers, BAS-RPL reduces buffer overflow drops by 87%, achieves higher delivery rates, and eliminates route oscillation in burst-prone IoT networks.
