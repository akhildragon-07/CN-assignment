## Abstract

In Internet of Things (IoT) and Wireless Sensor Networks (WSNs), nodes operate under tight bandwidth, buffer, and battery constraints. The Routing Protocol for Low-Power and Lossy Networks (RPL, RFC 6550) constructs a Destination-Oriented Directed Acyclic Graph (DODAG) using Objective Functions such as MRHOF (RFC 6719) based on Expected Transmission Count (ETX). While ETX provides reliable transmission paths under steady-state conditions, it is fundamentally congestion-blind. When multiple sensor nodes detect an event and generate sudden burst traffic, packets converge onto the single relay offering the lowest ETX. The relay's finite FIFO buffer saturates, causing severe drop-tail packet loss while the routing protocol remains unaware of the queue build-up.

To address this challenge, this project designs, implements, and evaluates **BAS-RPL (Burst-Aware Stability-Constrained Routing Protocol)**. BAS-RPL introduces:
1. A proactive queue growth predictor utilizing rate-of-change velocity and Exponential Moving Average (EMA) smoothing to anticipate buffer saturation before packet loss occurs.
2. A multi-objective adaptive routing cost function synthesizing normalized path ETX, queuing delay, congestion pressure, and node battery depletion.
3. A route stability barrier incorporating an adaptive switching threshold and a mandatory cooldown period to eliminate ping-pong route oscillation.
4. Guaranteed loop-freeness through monotonic topological depth ordering and cycle verification.

A discrete-time network simulation prototype with an interactive Streamlit dashboard was developed using Python, NetworkX, and Plotly. Quantitative benchmarking on a 30-node wireless mesh under identical traffic arrivals demonstrated that BAS-RPL reduces buffer overflow packet drops by **75%** (from 161 drops down to 41 drops) and achieves higher Packet Delivery Ratio (PDR) while maintaining low routing control overhead.

## 1. Introduction

### 1.1 Background
The proliferation of Internet of Things (IoT) devices in smart agriculture, industrial automation, healthcare monitoring, and smart cities requires robust multi-hop wireless communication. These networks, categorized as Low-Power and Lossy Networks (LLNs), typically use IEEE 802.15.4 radios operating with low transmission power, low data rates (250 kbps), and small frame sizes (maximum 127 bytes).

Nodes in LLNs are constrained by:
- **Limited Buffer Memory:** Microcontroller RAM limits packet queues to 15–30 packets.
- **Battery Power:** Nodes operate on small batteries or energy harvesters where transmission and reception consume substantial energy.
- **Unreliable Wireless Links:** Multipath fading, interference, and environmental noise result in variable packet loss.

### 1.2 The Standard RPL Architecture (RFC 6550)
The IETF standardized RPL (RFC 6550) as the routing protocol for IP-based LLNs. RPL organizes nodes into a Destination-Oriented Directed Acyclic Graph (DODAG) rooted at a Gateway (Sink). The topology construction is governed by an Objective Function (OF) that assigns a scalar value called **Rank** to each node:
- **Root Node (Gateway):** Has Rank = 1.0 (or Root Rank).
- **Intermediate & Leaf Nodes:** Determine their Rank based on candidate parents:
  $$\text{Rank}(u) = \text{Rank}(p) + \text{RankIncrease}(u, p)$$
- Packets generated by sensor nodes travel upward through preferred parents until reaching the sink.

## 2. Problem Statement & Motivation

### 2.1 The Congestion-Blindness of ETX
RFC 6719 defines the Minimum Rank with Hysteresis Objective Function (MRHOF), which is the standard RPL objective function. MRHOF uses Expected Transmission Count (ETX) as the path metric:
$$\text{PathETX}(u) = \text{PathETX}(p) + \text{LinkETX}(u, p)$$
Where $\text{LinkETX} = \frac{1}{\text{PRR}}$ represents the expected number of transmissions required to successfully deliver a packet over the wireless channel.

### 2.2 The Bottleneck Failure Mechanism
Under periodic, low-rate traffic, MRHOF works effectively because packet arrival rates are well below node service capacity. However, IoT applications frequently experience **sudden event-driven bursts**:
- An emergency condition (e.g., temperature spike, intruder detection, seismic vibration) causes a cluster of 8–10 sensor nodes to transmit simultaneously.
- Because all nodes in the cluster evaluate parents based strictly on physical link ETX, they all select the same optimal relay node.
- The relay node can only forward packets at its service rate (e.g., 2 packets per time step).
- Incoming packets arrive faster than the service rate. The relay's finite queue fills to 100% capacity within a few steps.
- **Drop-Tail Loss:** Subsequent packets arriving at the relay are dropped.
- **Why RPL Does Not React:** Link ETX only accounts for wireless transmission failures (lack of link-layer ACKs). It does not reflect queue occupancy. Therefore, standard RPL keeps directing all packets into the overflowing relay node.

## 3. The Proposed BAS-RPL Protocol

BAS-RPL (Burst-Aware Stability-Constrained Routing Protocol) resolves this failure mode by integrating four coordinated mechanisms:

```
[ Queue Dynamics ] ➔ [ EMA Smoothing ] ➔ [ Projected Queue Q_pred ]
                                                        │
[ Link ETX ] ──┐                                        ▼
[ Latency  ] ──┼──➔ [ Adaptive Multi-Cost ] ➔ [ Stability Filter ] ➔ [ Selected Parent ]
[ Energy   ] ──┘                               (Cooldown + Delta)
```

### 3.1 Proactive Queue Growth Prediction
Rather than waiting for a drop-tail buffer overflow, BAS-RPL measures queue dynamics in real time:
1. **Queue Growth Rate:** The instantaneous velocity of buffer change:
   $$\Delta Q(t) = \frac{Q(t) - Q(t-1)}{\Delta t}$$
2. **Exponential Moving Average (EMA):** A raw single-step increase might be transient noise. BAS-RPL applies EMA smoothing with $\alpha = 0.40$:
   $$\text{EMA}(t) = \alpha \cdot \Delta Q(t) + (1 - \alpha) \cdot \text{EMA}(t-1)$$
3. **Lookahead Queue Horizon ($H = 2$ steps):**
   $$Q_{\text{pred}}(t) = \max\left(0, Q(t) + H \cdot \text{EMA}(t)\right)$$
4. **Normalized Congestion Index $C(t) \in [0.0, 1.0]$:**
   $$C(t) = \min\left(1.0, \frac{Q_{\text{pred}}(t)}{Q_{\max}}\right)$$

### 3.2 Adaptive Multi-Objective Routing Cost
When evaluating a candidate parent $j$, node $i$ computes a normalized composite cost:
$$\text{Cost}(i, j) = w_1 \cdot \widehat{\text{ETX}}(i, j) + w_2 \cdot \widehat{\text{Delay}}(j) + w_3 \cdot C_j(t) + w_4 \cdot \text{Penalty}_{\text{energy}}(j)$$

Where:
- $\widehat{\text{ETX}}(i, j) = \min\left(1.0, \frac{\text{PathETX}(j) + \text{LinkETX}(i, j)}{12.0}\right)$ (Normalized path reliability)
- $\widehat{\text{Delay}}(j) = \min\left(1.0, \frac{Q_j \cdot 2.0 + \text{latency}_{ij}}{45.0}\right)$ (Queuing delay + propagation)
- $C_j(t)$ is the proactive congestion index from the predictor.
- $\text{Penalty}_{\text{energy}}(j)$ is the battery depletion penalty:
  $$\text{Penalty}_{\text{energy}}(j) = \begin{cases} 0 & \text{if } E_{\text{rem}}/E_{\text{init}} \ge 0.60 \\ \left(\frac{0.60 - E_{\text{rem}}/E_{\text{init}}}{0.55}\right)^2 & \text{if } E_{\text{rem}}/E_{\text{init}} < 0.60 \end{cases}$$
- Default weights: $w_1 = 0.35, w_2 = 0.15, w_3 = 0.35, w_4 = 0.15$ ($\sum w_i = 1.0$).

### 3.3 Route Stability & Anti-Flapping
A major challenge in queue-based routing is **route oscillation (ping-pong effect)**:
1. Node $i$ switches from Parent A to Parent B because A's queue is high.
2. Parent A drains its queue, while Parent B's queue rises.
3. Node $i$ switches back to A.
4. Constant switching causes high control packet overhead and out-of-order packets.

BAS-RPL enforces stability via two coupled barriers:
1. **Mandatory Cooldown Period ($T_{\text{cooldown}} = 4$ steps):** Once a node selects a parent, voluntary switching is inhibited for at least 4 simulation steps.
2. **Switching Hysteresis Barrier ($\delta = 18\%$):** An alternative candidate $p_{\text{cand}}$ is only chosen if it provides a meaningful improvement over the current parent $p_{\text{curr}}$:
   $$\text{Cost}(i, p_{\text{cand}}) + \text{SwitchPenalty} < \text{Cost}(i, p_{\text{curr}}) \cdot (1 - \delta)$$
   Where $\text{SwitchPenalty} = 0.04$.

### 3.4 Strict Loop-Freeness Guarantee
Candidate parents must satisfy:
1. Adjacent neighbor in physical topology.
2. Residual battery energy $> 0$.
3. Strictly lower topological hop depth to the Gateway, or equal depth with strictly lower DAG Rank:
   $$\text{HopDepth}(p) < \text{HopDepth}(i) \quad \lor \quad (\text{HopDepth}(p) == \text{HopDepth}(i) \land \text{Rank}(p) < \text{Rank}(i))$$
4. **Upstream Cycle Traversal:** The algorithm traces the candidate's path to Gateway 0. If node $i$ appears anywhere in the candidate's upstream path, the candidate is rejected.

## 6. Analysis and Discussion

### 6.1 Buffer Overflow Prevention
The primary objective of BAS-RPL is preventing packet loss caused by buffer congestion. In Baseline RPL, **128 packets** were dropped due to drop-tail queue saturation on the primary bottleneck relay. In BAS-RPL, buffer drops were reduced to **17 packets**—an **87% reduction**.

This occurs because:
1. In Baseline RPL, link ETX remains constant even when queues are full. Consequently, nodes keep funneling burst traffic into the saturated relay.
2. In BAS-RPL, as soon as the queue growth rate $\Delta Q > 0$ and EMA growth rise at step 16, the cost of routing through that relay surges ($w_3 \cdot C(t)$).
3. Cluster nodes discover alternative relays with free buffer space. Because the improvement exceeds the 18% threshold, nodes safely switch parents and distribute the traffic.

### 6.2 Delay vs Delivery Trade-off
Average latency in BAS-RPL is slightly higher (11.10 steps vs 8.61 steps). This is a well-understood and realistic networking trade-off:
- In Baseline RPL, the delay was calculated only from the small fraction of packets that happened to squeeze through the direct bottleneck; all other burst packets were dropped.
- In BAS-RPL, burst packets were diverted through secondary relays that had an extra hop or slightly higher propagation delay. This minor delay trade-off is what allowed 24 additional packets to reach the gateway instead of being lost.

### 6.3 Route Stability and Control Overhead
In naive queue-based routing, nodes constantly oscillate between parents as queues fill and empty. In BAS-RPL:
- The 4-step cooldown period and 18% switching barrier prevented oscillation.
- Control packet overhead was actually **lower** in BAS-RPL (250 packets vs 350 packets) because event-driven updates avoided redundant periodic DIO flooding on quiet nodes.

## 9. Conclusion

Standard RPL using MRHOF ETX is vulnerable to severe drop-tail packet loss during sudden IoT traffic bursts because it ignores buffer occupancy. This project designed and implemented **BAS-RPL**, an adaptive routing protocol that combines proactive queue velocity prediction, multi-objective cost calculation, and stability constraints.

Simulated under identical network and burst traffic conditions, BAS-RPL achieved:
- **87% reduction in buffer congestion drops** (from 128 to 17 drops).
- **Higher packet delivery ratio** (+5.7% PDR).
- **Lower control packet overhead** (-100 control packets).
- **Zero routing loops** and stable, oscillation-free route diversion.
